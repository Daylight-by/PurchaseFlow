# 采购询价与审核：演示业务规则

本项目是从既有“销售单 → 采购询价 → 审核 → 利润核算”经验中抽出的一段教学原型。供应商、报价和订单数据均为模拟数据；规则用于展示 ABP 开发能力，不代表任何公司的实际制度。

## 一条可演示的流程

1. 采购员创建采购需求，填写关联销售单号、预计销售金额和需求说明。
2. 采购员录入至少两条供应商报价，包含供应商名称、采购金额、交付天数和备注。
3. 采购员选择一条报价并填写选择理由，然后提交审核。
4. 审核人查看两条报价、选择理由和预计毛利，批准或退回并填写意见。
5. 已批准的需求冻结；退回的需求可修改后重新提交。每次提交、批准和退回均写入业务操作记录。

预计毛利 = 销售金额 − 所选采购报价。数值只是演示用的预计值，不包含税费、履约成本等现实因素。

## 必须由后端执行的约束

- 销售金额、报价金额必须大于零；交付天数不能小于零。
- 同一租户的销售单号不能重复；应用服务先给出可读错误，数据库唯一索引防止并发时写入重复值。宿主数据的 `TenantId` 为空，另有部分唯一索引。
- 只有草稿或已退回的需求可以编辑报价和选择方案。
- 提交时至少有两条报价，并且选中的报价必须属于该需求。
- 待审核和已批准的需求不能修改报价；已批准的需求不能再次提交。
- 只有拥有审核权限的用户可以批准或退回，审核意见随结果一并记录。
- 采购员只能修改自己创建的需求；审核员可以审核同一租户内的待审核需求，但不能因此获得编辑权限。
- 所有业务记录属于当前租户；通过另一租户的 ID 请求也不能读取或修改。
- 提交和审核操作中的状态与业务记录由同一个 EF Core DbContext 在一个保存批次中写入。SQLite 演示版沿用 ABP 模板的非事务性 UoW 配置；若切换到正式数据库，需重新验证事务与并发行为。

## V2 比较与提示的边界

`QuoteDecisionAnalyzer` 是无 I/O 的纯计算器，提供至少两条报价、有效选择、理由非空三项准备检查，及并列最低价、最快交期和预计毛利率。检查齐全不代替状态、登录、权限或创建者检查。

所选采购价高于销售金额时提示负预计毛利。若存在金额不更高且交期不更慢、至少一项严格更好的报价，则选中方案有“价期均不占优”提示；它不包含质量和服务，因此两种提示均不新增提交阻断规则。

浏览器实验台按当前集合归一化金额和交期，默认 70/30 加权；全部相同的指标均为 100 分。它只改变临时排名，不发写请求、不保存权重、不替换服务端选择。当前项目运行时不调用 AI 决策。

Dashboard 在当前租户范围内统计数据；已批准采购额和预计毛利只包含选中报价确实属于该需求的记录。简报取当前详情 DTO，打印后是当时的快照，不能替代电子签章或不可篡改归档。本轮未新增数据库字段或迁移。

## 示例金额

销售金额 100,000 元；供应商 A 报价 82,000 元，10 天交付；供应商 B 报价 86,000 元，5 天交付。采购员选择 B 并说明交付时间原因，预计毛利为 14,000 元。审核人可据此批准或退回。
